# fuck-anthropic guard — 使用说明

[English](UserGuide.en.md) | **简体中文**

适用0.4.4测试版 / build13.0，要求macOS14+。这是实验性Surge配套工具，不是旧SSH转发版本。

## 1. 保护范围

Guard识别签名验证通过的Claude Desktop、原生Claude Code及可可靠追溯的同用户子进程。可选系统过滤器将它们限制到已验证的本机Surge TCP入口。其他用户、代理基础设施及未知归属不在已证明的覆盖范围内。

**Surge负责转发。Guard不提供VPN/代理/SSH，不修改系统网络，不读取VPS私钥。**

```text
Claude -> Guard系统过滤 -> Surge专用入口 -> 代理节点 -> 网站
```

## 2. 安装与升级

下载明确版本的公证Universal2 ZIP，解压后将一份App放入Applications。Apple Silicon和Intel均编译，Intel未做真机验收。安装与启用保护是两件事。

升级前保存工作并退出Claude客户端，保持Surge运行。退出Guard时保留过滤器，替换App后打开并明确恢复/启用检查，完成可能出现的macOS扩展授权。界面就绪前不要重开客户端。系统若要求重启，重启后复核保护再使用。不要同时运行共享同一bundle标识的新旧副本。

旧SSH版本迁移需在客户端关闭时单独安排，不要启动归档转发器，也不要仅为变绿而停用保护。卸载时先关闭受保护客户端，再明确停用并确认，最后退出App。

## 3. 准备Surge专用入口

共享代理可能合法地将其他流量DIRECT，所以保护需要独立HTTP监听，例如127.0.0.1:6154，并用首条`IN-PORT`规则固定到单个受支持Hysteria2节点。

将以下示例合入自己的配置，不要整份覆盖或重复组名；Guard不会替你修改。

```ini
[General]
http-listen = 127.0.0.1:6152, 127.0.0.1:6154

[Proxy Group]
CLAUDE-LOCKED = select, Hysteria2

[Rule]
IN-PORT,6154,CLAUDE-LOCKED
# 必须是第一条有效规则，其他规则放在后面。
```

Hysteria2节点由Surge配置。专用策略只能选择一个节点，不得包含DIRECT备用、嵌套组或脚本分流；MITM、脚本、重写及临时规则必须关闭/为空。不支持或发生变化的配置不发放许可。TLS由Surge管理，Guard不会绕过CLI对隐藏节点字段的脱敏。

## 4. 配置与启用

1. 保护停用时，在设置与诊断打开“配置入口…”。
2. 输入专用端口、预期出口IPv4/IPv6地址和单节点策略名；错误会在原弹窗内提示并保留输入，取消不保存。
3. 验证保存读取签名Surge CLI与生效配置，存储非秘密的入口/出口/策略条件及配置摘要，不保存节点密码。
4. 启用保护并完成macOS授权；经同意的不含账号探针通过Surge访问`api.ipify.org`。
5. 就绪需要新鲜匹配的出口证据、稳定规则、监听进程身份和过滤器确认。已配置或状态不明时入口只读。“重新检查”重试控制连接，不会偷偷启用保护或改写Surge。

## 5. 启动客户端

已识别客户端必须连接专用本机TCP入口；外网直连、其他端口和直接UDP/QUIC会被拒绝。Surge自身的上游协议不受客户端规则限制。普通Dock启动可能使用共享代理，因而被拦截。

可选启动脚本先验证原生客户端签名，仅为新进程设置代理，不退出已有Desktop、不启动代理，也不改系统设置。

```bash
bash scripts/launch-claude-via-surge.sh desktop 6154
bash scripts/launch-claude-via-surge.sh cli 6154
```

不是已识别的签名原生程序时，名称相同或启动成功不证明受保护。独立包装器和孤儿子进程可能无法追溯。

## 6. 状态和记录

| 状态/操作 | 含义 |
|---|---|
| 保护已就绪 | 已识别客户端可使用最近验证的路径，不代表网站请求成功或全局覆盖。 |
| 连接已阻断 | 没有连接许可；明确恢复检查后才重新验证。 |
| 正在确认保护 | 执行或证据尚未确认，不能视为已保护。 |
| 保护未开启 | 系统过滤未启用。 |
| 阻断Claude连接… | 确认后撤销许可并中断已跟踪连接。 |
| 停用保护… | 确认后明确移除阻断保护。 |
| 关闭窗口 | 主程序继续运行，可从Dock或菜单栏打开。 |
| 保持阻断并退出 | 退出主程序并保留过滤器，撤销连接许可。 |

日志仅在过滤器内存保留最近80条受保护客户端元数据，扩展重启后清空。可按身份/PID/目标搜索、排序、查看详情和复制。允许表示入场检查通过；拒绝次数也包含后续撤销，不一定是唯一连接数。`127.0.0.1:6154`是本机代理，不是最终网站。触发代码说明当时观测到的失败类别，缺失历史细节不会被臆测补全。

“归属未知”不是泄漏次数或拦截次数，只揭示归属缺口，不保留其他应用的连接历史。不记录包正文、聊天、URL路径或凭据。

## 7. 界面、菜单栏与通知

语言切换不改变保护状态；正式程序记住语言和外观，系统对话框及进程/网络名称遵循各自语言。菜单栏显示状态、已识别进程数、入口和最近过滤器确认时间，符号随状态变化；重新检查调用实际检查，打开主窗口进入完整面板。

客户端页列出已识别进程，退出前确认并再次核对身份后发送SIGTERM。先保存工作，不自动强杀。IPv6仅展示物理网络服务设置，不证明互联网可达性。

通知权限、专注模式及系统设置可能阻止横幅。提醒表示安全许可丢失，不把执行未知说成已阻断，以App状态为准。

## 8. 验收边界与开发

周期性配置/出口检查不是逐请求的密码学路径证明，发现配置变化存在观察窗口。过滤器崩溃、物理网络变化、开机早期流量、整机重启/唤醒与未知归属需单独实机验收。签名和公证不证明零IP暴露或账号资格。见[安全模型](../SECURITY.zh-CN.md)和[验证状态](FEATURE-STATUS.zh-CN.md)。

开发使用 **01 Preview (Safe)** 的离线数据。`App/main.swift`中四个`#Preview`通过Xcode Canvas显示正式菜单栏共用的AppKit视图，仅在`CCW_CANVAS`启用。Canvas验证内容布局，不等于真实系统入口位置和完整点击验收。生产scheme只构建。见[贡献指南](../CONTRIBUTING.zh-CN.md)。
