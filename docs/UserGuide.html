CLAUDE / LOCAL NETWORK

Claude Connection Watcher 使用说明书

适用：0.4.0 / build 12.0，Surge 配套版。状态：开源预发布候选，尚未完成系统级故障场景的实机验收。

1. 这个 App 做什么

只做两件事：显示已识别的 Claude 进程、提供退出操作并查看物理网络服务的 IPv6 设置；通过 macOS 系统过滤器限制已识别 Claude 客户端的连接。

联网由 Surge 负责。Watcher 不提供代理、VPN 或 SSH 通道，不读取 VPS 私钥，也不清理账号凭据。

Claude → Surge 专用本机入口 → 单个 Hysteria2 节点 → 你的 VPS
           ↑
Watcher 验证入口、有效规则与出口，并允许或阻断已识别的连接

2. 预览与正式程序有什么区别

程序用途
Watcher Preview离线模拟界面。不会读取真实进程、发送探针、退出应用或启用过滤器
Claude Connection Watcher正式代码。进程/IPv6查看可单独使用；网络保护需配置、签名与系统批准
Xcode 的生产 scheme只构建，不自动安装或启动过滤器

macOS 14 或更高版本。Apple Silicon 与 Intel 可从源码构建。正式系统过滤器需要有效且匹配的 Developer ID / Network Extension 配置；仅编译成功或 ad-hoc 签名不代表系统允许加载。

不要同时运行新旧生产版。旧版若还启用专用 SSH 保护，先在旧版中明确停用它；新版不会自动继承或重启旧通道。

3. 只查看进程和 IPv6

打开 App 即可查看可验证身份的 Claude Desktop、原生 CLI 和能可靠追溯的后代。不会因为一个任意进程名字带有 Claude 就把它当成退出目标。

点击“退出所列Claude进程…”后，会显示确认。执行前重新核对 PID、所属用户、启动时间与路径，再发送正常终止信号。没有自动强制杀进程；未退出的进程会继续显示。请先保存工作。

IPv6 按 Wi-Fi / 以太网服务显示：关闭、自动、手动或未知。这里只读取设置，不修改它。Wi-Fi IPv6 关闭不等于回环、AWDL、VPN 等所有接口都没有 IPv6；设置开启也不证明 IPv6 外网已连通。

4. 为什么保护模式需要 Surge 专用入口

普通 Surge 6152 入口可能同时承载 Xcode 直连、国内直连和代理流量。仅证明 Claude 连接了 6152，不能证明其所有目标都经过 VPS。

因此这个候选的严格模式使用 Surge 自己监听的独立 HTTP 入口，例如 127.0.0.1:6154。Watcher 不监听这个端口。Surge 用最优先的 IN-PORT 规则把这个入口固定到一个 Hysteria2 节点；其他入口仍保留原有分流。

App 不会替你修改 Surge。 下列只是合并示例：保留原配置、原监听项与其他规则，不要整份覆盖，不要重复添加同名策略组。

[General]
http-listen = 127.0.0.1:6152, 127.0.0.1:6154

[Proxy Group]
CLAUDE-LOCKED = select, Hysteria2

[Rule]
IN-PORT,6154,CLAUDE-LOCKED
# 上面必须是实际生效的第一条规则
# 原有 Xcode DIRECT、其他规则留在后面

Hysteria2 节点由你在 Surge 内配置。示例不包含服务器凭据。专用策略不能带 DIRECT 备用项、嵌套策略组或脚本路由；当前验证器只支持单个 Hysteria2 节点。MITM、脚本、重写和临时规则必须关闭或为空，不支持的配置会拒绝发放许可。

5. 配置并启用保护

  1. 在没有进行重要 Claude 工作时准备以上 Surge 配置；先保留配置备份。
  2. 在 Watcher 点“配置Surge检查…”，填写专用 HTTP 端口、预期 VPS 出口 IP、策略组名称。
  3. “验证并保存”只读查询 Surge 的签名 CLI、有效配置与专用规则，保存公开检查条件及配置摘要，不保存节点密码。
  4. 点“启用保护…”，阅读提示并完成 macOS 对网络过滤器的批准。
  5. 验证会通过 Surge 访问 api.ipify.org，不发送 Claude 账号、Cookie 或 API key。只有出口匹配、规则稳定、代理归属和过滤执行得到确认，才显示放行。

Surge CLI 会隐藏部分节点字段。本程序不会绕过隐藏去读取口令，也不声称独立验证了所有隐藏字段；节点 TLS 配置仍由 Surge 管理。

6. 让 Claude 使用正确入口

保护模式启用后，识别出的客户端只能连接配置的专用入口；直接连外网、UDP 或其他代理端口会被拒绝。正常从 Dock 启动的 Claude 可能继续使用系统的 6152 入口，因此可能被阻断。

源码提供可选启动脚本，给本次客户端进程设置 Surge 代理；它不创建代理、不改系统代理、不启用过滤器：

bash scripts/launch-claude-via-surge.sh desktop 6154
bash scripts/launch-claude-via-surge.sh cli 6154

脚本要求已安装的官方客户端签名有效；Desktop 已运行时拒绝复用。先自行正常退出原有客户端，避免旧参数继续生效。仅进程查看模式不要求使用这个脚本。

7. 看懂状态和退出方式

状态或操作含义
系统保护未启用只有查看功能，不能依赖 App 阻断
系统过滤执行未确认不知道过滤器是否真正工作，不能按“已保护”理解
已识别的Claude连接：阻断中正在等待条件、条件失败，或你选择了保持阻断
已验证Surge专用路径最近的有限时效检查通过；不是所有未来连接的安全保证
保持阻断停止发放放行许可，保留过滤器
停用保护…明确停用系统过滤；此后不再提供拦截
关闭窗口程序继续运行，可从 Dock 或菜单栏重新打开
保持阻断并退出主程序退出，过滤器保留并在许可失效后阻断
停用保护并退出停用过滤后退出；组件仍可能安装在系统中

配置变化需要重新确认和保存。不要通过随意换端口或关闭过滤器，把失败状态解释成已经恢复安全路径。

8. 安全边界：请完整阅读

这是实验性防护，不是经过长期验证的生产安全产品。

  • 仅覆盖可靠识别的官方客户端与后代；身份缺失、孤儿进程或其他包装器可能不在覆盖范围。不会为了未知进程把全机流量一概阻断。
  • 系统过滤器自身崩溃、被禁用、macOS 重启最早阶段的行为尚未全面验收。不能保证任何崩溃都不泄漏。
  • 使用短期许可与周期性配置/出口检查。Surge 规则变化到被发现之间存在时间窗口；出口探针不能证明每一条应用请求都采用同一路由。
  • socket 数据过滤和“远端从未看到任何 IP 包”不是同一保证。禁止宣称 TCP 首包、DNS、UDP、IPv6 及所有系统代理进程都已经零泄漏。
  • 退出进程可能中断工作；正常退出失败时不会自动强杀。
  • 只读监测、签名、公证、开源和离线测试，都不等于全面独立安全审计或 Claude 账号不会受限。

测试时使用无账号客户端和隔离样例。不要在重要会话进行中关闭 Surge、切换网络或安装试验过滤器。

9. 故障排查

问题优先检查
专用入口未验证端口是否由真实 Surge 监听，而非其他进程；不要使用共享 6152/6153
规则未通过有效第一条是否为对应 IN-PORT；是否单节点；有无临时规则或脚本
出口不匹配或探针超时查看 Surge 自身连接与节点状态；不要改成 DIRECT 作为备用
扩展执行未知查看系统设置中的网络过滤权限、签名是否匹配；不要只看 App 窗口存在
开启保护后 Claude 不联网是否仍使用共享端口或旧启动参数；使用正确 Surge 入口再验证
进程列表不全检查客户端版本、签名和进程归属；未知进程不会仅凭名称被退出

10. 更新、开发和隐私

默认 bash scripts/build.sh 或 Xcode 的 01 Preview (Safe) 构建离线预览。CCW_BUILD_MODE=host 构建主程序与过滤器，不会安装。正式签名需要你自己的合法开发配置，不能把签名私钥上传到仓库或 CI。

源码、Git 历史、图片和精确产物在发布前分别审查；公开配置只能使用文档示例地址。不要提交 SSH 私钥、代理密码、Cookie、钥匙串或个人运行日志。

本版本不提供账号凭据归档/清理、IPv6 设置修改、SSH 转发、VPS 登录或自动主备切换。功能与限制见 PRD；测试状态见 FEATURE-STATUS。
